Bearing

12 November 2026 · 11:34

Seven months after LocalStack archived its Community Edition and put an auth token in front of everyone’s CI, AWS ships AWS Emulator free as in free beer (and, being CC0, free as in speech too). The tool was written entirely by our friendly agent bots (see, I’m your friend, and I’d like to survive Skynet), and following the new tradition of “If I’m not writing or reading it, why not Rust?”

As always, you can use AWS_ENDPOINT_URL to point your existing CLI scripts, SDK tests, and coding agents to the in-memory AWS API simulator. Each instance gets its own port, keys, and state, so parallel test suites and agents never see each other’s tables. The generated access keys all start with EMULATOR (a small mercy for anyone who has pasted the wrong credentials into the wrong terminal).

AWS publishes a fidelity score per service, ‘k’ of ‘n’ tests matching real AWS on status code, body, and exact error message, and the suite is public on GitHub (when available, zing), failing tests included. Unsupported operations return a 501 instead of pretending.

Before you delete your LocalStack config, consider the existing gaps. AWS Emulator fidelity is closer to the real thing on the control plane (create a bucket, describe a table), but coverage is mixed on the data plane, so be careful about going all in using complex CloudFormation, Terraform, or CDK stacks. It still does not evaluate IAM policies, so a request AWS would deny can succeed locally, and it is a single account with no cross-account or cross-Region behaviour. Your application state lives in memory only.

AWS provides Debian and RPM packages, but for Windows and macOS you get a Dockerfile to build your container locally. Telemetry is on by default, so be mindful of it with your CI flow.
